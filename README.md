# 貓狗大戰 🐱 vs 🐶

一隻貓、一隻狗站在畫面左右兩側的地形上，中間隔著一道圍牆。
兩邊輪流調整**角度**與**力道**發射砲彈（貓丟毛線球、狗丟骨頭），
砲彈受**重力**與**風向**影響畫出拋物線，命中對方就扣血，爆炸還會把地形炸出坑洞。
先把對方血量打到 0 的一方獲勝。

- **單機對戰**：對電腦，三段難度（簡單／普通／困難）。
- **線上對戰**：兩位玩家在**不同電腦**上連線對戰，一個選貓、一個選狗。
- **觀戰**：其他人可以進房只看不打，看得到盤面、操作摘要與聊天室，但不能出手。
- **道具資訊**：雙方剩餘道具會直接顯示在戰場天空左右兩側，玩家與觀戰者都看得到。
- **邀請連結**：一鍵產生有期限、有使用次數、可撤銷的連結，貼給朋友就能進來。
- 全繁體中文介面，手機／平板／桌機、直向橫向都可以玩。

## 1. 快速開始（本機）

需要 **Node.js 18 以上**（開發時使用 v24）。

### Windows 最省事的方式

雙擊 **`啟動遊戲.bat`**。
第一次會自動 `npm install`，接著啟動伺服器並開啟瀏覽器。

### 指令列

```bash
npm install     # 第一次才需要
npm start       # 啟動伺服器，預設 http://localhost:3020
```

啟動後畫面會印出這樣的資訊：

```
========================================
  貓狗大戰 伺服器已啟動
========================================
  本機：      http://localhost:3020
  同網段：    http://192.168.1.20:3020   ← 另一台電腦用這個
  健康檢查：  http://localhost:3020/health
  允許來源：  不限制（* — 正式環境請設定 GAME_ALLOWED_ORIGIN）
  回合時限：  15 秒
----------------------------------------
```

換一個埠：

```bash
# macOS / Linux
PORT=4000 npm start
# Windows PowerShell
$env:PORT=4000; npm start
```

## 2. 讓另一台電腦連進來

### 方式 A：同一個 Wi-Fi／區域網路（最快，不用部署）

1. **A 電腦**執行 `npm start`（或雙擊 `啟動遊戲.bat`），
   記下畫面印出的「同網段」網址，例如 `http://192.168.1.20:3020`。
2. **A 電腦**在瀏覽器打開 `http://localhost:3020` →
   「線上對戰」→「開一間房」→ 在房間畫面按 **🔗 產生** 拿到邀請連結。
3. 把邀請連結傳給對方（LINE、訊息、口頭唸房號都行）。
   > ⚠️ 邀請連結裡的網域是「A 電腦目前打開的網址」。
   > 如果 A 是用 `localhost` 開的，連結會是 `http://localhost:3020/?room=...`，
   > 對方打不開。**A 電腦請改用區網網址 `http://192.168.1.20:3020` 開頁面**，
   > 這樣產生的連結才會是對方也能打開的。
4. **B 電腦**在瀏覽器貼上那個連結，或直接開 `http://192.168.1.20:3020`
   →「線上對戰」→ 在大廳的房間列表按「加入對戰」，或輸入 4 碼房號。
5. 兩邊各選一邊（貓／狗，不能重複）→ 各自按「準備好了」→ 房主按「開始對局」。

連不上時的檢查順序：

| 症狀 | 檢查 |
| --- | --- |
| B 電腦打不開網址 | 兩台是不是在同一個 Wi-Fi／網段 |
| 打得開但一直轉圈 | A 電腦的防火牆是否擋住 Node.js 的 3020 埠（Windows 第一次啟動會跳出詢問，選「允許存取」） |
| 邀請連結打不開 | A 電腦是不是用 `localhost` 開頁面（見上面第 3 點） |
| 房間突然不見 | 伺服器重啟過；房間只存在記憶體裡 |

### 方式 B：不同網路（部署到雲端）

見 [第 11 節](#11-部署到免費雲端)。部署完成後把服務網址給對方即可，
兩台電腦在世界任何角落都能對戰。

### 方式 C：前端與伺服器分開

如果前端另外放在 GitHub Pages 之類的靜態空間，在網址後面加上 `?server=`：

```
https://你的帳號.github.io/cat-dog-war/?server=https://你的伺服器網址
```

或在建置時注入（見 [第 10 節](#10-環境變數與-server-url-參數化)）。

## 3. 遊戲規則

| 項目 | 數值 |
| --- | --- |
| 初始血量 | 100 |
| 身體正中直接命中傷害 | 20 |
| 直接命中判定 | 基準尺寸 34，依頭／身體／腿部輪廓判定（比舊版 22 寬鬆） |
| 爆炸傷害範圍 | 半徑 84（核心 30 之內依部位吃滿傷害，之後依距離遞減到 0） |
| 角度範圍 | 0°–89° |
| 力道範圍 | 10–100 |
| 風力範圍 | −10 ～ +10（每回合重新決定） |
| 出力係數 | 滿血 100%、血量歸零 72%，中間線性 |
| 補血回復量 | 30 |
| 每次出手時限 | 15 秒（單機與線上都適用） |

- 貓在左（站在開蓋的垃圾桶上）、狗在右（站在房子前的木平台上），**輪流**出手。
  兩邊的站台**一樣高**，沒有人佔到地形便宜。
- 中間隔著一道**柵欄**。柵欄畫的位置與高度就是碰撞判定用的地形本身，
  不會出現「球穿過畫出來的柵欄」這種騙人的畫面。
- **地形固定不變、貓狗位置固定**：爆炸只扣血，不會改變地圖。
  所以同一組角度與力道在整局裡永遠打到同一個點 —— 抓到準心就能重複命中。
- 砲彈受**重力**（向下）與**風**（水平）影響；風向與風力兩邊都看得到，不是隱藏資訊。
- 打中對手身上 → 依命中部位計算傷害（頭部爆擊、身體標準、腿部較輕）；打在附近地上 → 依距離遞減；**打到自己腳邊也會自傷**。
- 命中頭部會出現 **💥 爆擊**，傷害約為身體正中的 1.65 倍；命中腿部約為 0.75 倍，身體與落點距離則讓每發傷害不會固定不變。
- **血量越低，同樣的力道飛得越近**。出力係數只由血量決定（公開、可預測、沒有亂數），
  受傷之後要把力道調更大才打得到 —— 落後的一方會越來越難打。
  蓄力時直接看畫布上的力道讀數；操作摘要只保留當下最重要的資訊。
- **勝負**：持續輪流出手直到一方血量歸零；血量先歸零者落敗，兩邊同時歸零算平手。
- **主動結束**：參賽者可以在設定裡按「投降」，投降者落敗；線上對局中離開房間也視同投降，對手不戰而勝。
- **出手時限**：單機與線上每次出手都只有 15 秒；時間到會自動跳過該回合，對局不會因此結束。
  出手時間到，伺服器會自動跳過那一回合並寫進操作摘要。

### 彈藥

貓丟**魚骨頭**、狗丟**狗骨頭**。兩者的物理完全相同，只是外觀不一樣。

### 道具（開局各一個，用完不補）

雙方開局各拿到四種道具**各一個**，用完就沒有了。
**一回合最多只能用一個，不能疊加。**

| 道具 | 效果 | 怎麼用 |
| --- | --- | --- |
| ✌️ 雙擊 | 用同一組角度與力道**連丟兩發**。地形和站位都不會變，所以兩發落點相同、傷害等於加倍（最高 40）。 | 在自己天空側的道具按鈕選起來 |
| 🦴 大骨頭 | 砲彈變大一圈：命中判定半徑 34 → 48（比較容易擦到），滿傷 20 → 30。爆炸範圍不變。 | 在自己天空側的道具按鈕選起來 |
| 💣 臭彈 | 換成臭氣炸彈：爆炸範圍 84 → 130、核心 30 → 48、滿傷 20 → 32。命中判定半徑不變。 | 在自己天空側的道具按鈕選起來 |
| 💖 補血 | 立刻回復 30 點血（不超過上限），**這一回合就換對手出手**，不發射。 | 按自己天空側的 💖 道具 |

- 大骨頭是「**比較好打中**」，臭彈是「**打不準也有傷害**」，兩者定位不同。
- 補血是唯一會**放棄這一回合攻擊**的道具：血量低時它同時止血又救回出力係數，
  但等於白送對手一發，要挑時機。
- 雙方剩餘的道具會放在戰場天空左右兩側，**觀戰者也看得到** —— 這遊戲沒有隱藏資訊。

### 地圖種子

單機模式可以輸入 6 碼種子（只認 A–Z 與 2–9，不含容易看錯的 0、1、I、O）。
**同一組種子會生出完全相同的地形與整串風向**，方便跟朋友比同一張地圖。
線上房間每一局都由伺服器隨機出種子，並顯示在系統訊息裡。

## 4. 操作方式

主要操作是**按住戰場、移動瞄準、持續蓄力、放開發射**，瞄準和蓄力放在同一個手勢裡。畫面下方控制列已移除，讓戰場可以放大：

1. **戰場瞄準＋蓄力**（滑鼠、手機、平板都一樣）
   畫布上方會顯示操作提示；按住戰場並移動，移動方向會調整角度，持續按住會從 10 蓄到 100，**放開就發射**。快速點一下則只保留瞄準結果，不會誤射；不想發射時把手指拖出戰場再放開即可取消。
   平板上的道具、聊天室與設定關閉按鈕都保留較大的觸控命中區，蓄力箭頭與畫布上的力道讀數會跟著手勢更新；角度只用箭頭呈現，不顯示數字。
2. **道具**
   自己那一側天空的道具按鈕可以選擇雙擊、大骨頭或臭彈；選定後本回合不能更換，按「↺ 重置」只會重設角度與力道、保留已選道具；💖 補血按下就會使用。對手那一側只顯示剩餘數量，不能誤觸。
3. **鍵盤**
   `←` `→` 調角度、`↑` `↓` 調力道（按住 `Shift` 一次調 5）、`空白鍵` 或 `Enter` 發射。

鍵盤是給不方便用蓄力手勢的人的等效替代方案，功能完全一樣。

蓄力時戰場虛線末端會顯示箭頭，箭頭越大代表力道越大；平時則顯示圓點。
上一發的軌跡會以淡虛線留在畫面上當參考（可在設定裡關掉）。
因為地形固定，這條參考線在整局裡都準 —— 上一發打哪，同樣的數值就會再打到那裡。

## 5. 電腦對手的三段難度

三段難度用的是**完全相同的規則與同一個物理引擎**（`public/js/rules.js` 的 `simulate`），
不會偷看資訊、不會偷改傷害、也不只是名稱不同。差別在三件可以直接觀察到的事：

| | 搜尋預算 | 風向補償 | 瞄準誤差 |
| --- | --- | --- | --- |
| **簡單** | 不試算，只用真空拋物線公式抓力道 | 0%（當作沒有風） | ±9°、±12 力道 |
| **普通** | 粗網格約 60 次試算 + 一輪收斂 | 55% | ±4°、±5 力道 |
| **困難** | 細網格約 300 次試算 + 兩輪收斂 | 100% | ±1.5°、±2 力道 |

`npm test` 會用 80 組固定種子量化這個差異，實測結果：

```
平均落點誤差：簡單 460、普通 119、困難 24
造成傷害的比例：簡單 36%、普通 80%、困難 99%
每發思考時間：簡單 0.0 ms、普通 0.1 ms、困難 0.7 ms
```

線上房間裡的電腦對手由**伺服器**持有並出手，任何用戶端都不能代替電腦決定行動。

## 6. 線上房間、觀戰與邀請連結

### 房間生命週期

```
建立房間 → 選邊（貓／狗，不可重複）→ 準備 → 房主開始
   → 輪流出手（伺服器驗證每一發）→ 分出勝負
   → 雙方同意「再來一局」→ 回到對戰
```

- **大廳**：房間列表顯示房號、房名、狀態（等待中／對戰中／已結束）、
  兩邊席位是誰、觀戰人數與目前回合，並提供「加入對戰」與「👀 觀戰」。
- **房主**：第一個進房的人；離開後自動移交給下一位。可以開始對局、補電腦對手、禁言。
- **斷線**：座位保留 60 秒，重新整理或短暫斷網後可以回到原位（靠瀏覽器裡的裝置識別碼）。
- **回收**：最後一位使用者離線後 5 分鐘自動關閉；斷線座位仍會先保留 60 秒供重新連線，但不會因此重新起算空房時間。

### 觀戰

- 觀戰者看得到**完整盤面、操作摘要與聊天室**（這個遊戲沒有隱藏資訊）。
- 觀戰者**不能**選邊、準備、開始、發射、投票再來一局、產生邀請連結。
  這些限制由**伺服器**把關：就算繞過畫面直接送事件，也會被擋下並回傳原因。
- 席位還有空且對局尚未開始時，觀戰者可以按「🐾 加入對戰」下場。
- 席位已滿時想當玩家的人會被**明確告知**改為觀戰，不會默默佔位或冒充玩家。

### 邀請連結

- 格式：`https://伺服器位址/?room=房號&invite=token`
- token 是 32 個十六進位字元（16 bytes 亂數），猜不到。
- 可以指定角色：**以玩家加入** / **以觀戰加入** / **看有沒有空位**。
- 預設有效 60 分鐘、最多 20 次，可以隨時**撤銷**。
- **每一次加入與重新連線伺服器都會重新驗證**，不是只在產生當下檢查一次。
- 無效、過期、已撤銷、次數用完、房間不存在都會回傳可讀的中文原因。

### 操作摘要與聊天室

- **操作摘要**改成左上方 📋 按鈕拉出的窄版浮層，不佔用戰場寬度；
  只保留目前回合、可做什麼、風向、雙方血量、剩餘時間與最近出手紀錄。
  雙方道具數量直接顯示在戰場天空左右兩側。
- **聊天室**固定在戰場左下角，預設收合成一顆藥丸按鈕並顯示未讀數；摘要展開時會自動讓出左側空間，避免兩個浮層互相遮住。
  訊息在伺服器消毒（去控制字元、限長 120 字）、限制頻率（0.7 秒）、支援房主禁言。
  觀戰者的發言會標示「（觀戰）」。

## 7. 畫面配置與 RWD

| 尺寸 | 配置 |
| --- | --- |
| **桌機 / 平板橫向（≥ 980px）** | 戰場佔滿主畫面，道具在天空左右兩側，摘要從左上方 📋 浮層開啟；主畫面取得剩餘空間 |
| **平板直向 / 手機（< 980px）** | 戰場維持主畫面，道具縮成天空兩側的按鈕，摘要從左側滑出；手機直向開摘要時聊天室暫時收合 |
| **手機直向** | 血量卡壓縮成一整列，控制列移除，畫布取得更多高度 |
| **手機橫向（高度 < 520px）** | 壓縮留白與字級，優先保住戰場、血量與道具 HUD；隱藏次要提示文字 |

- 戰場畫布依可用空間等比例縮放，**世界座標固定 1200 × 640**，
  所以手機和桌機打出來的彈道完全一樣。直向手機多出來的高度會拿去顯示更多天空，高吊球才看得到。
- **右上角的 ⚙ 系統設定鈕**在所有畫面都固定在安全區內（至少 48×48），
  按下開啟 **Modal 彈窗**（不是另一頁、也不是抽屜），只放全域的背景音樂、
  遊戲音效、聊天提示音、震動回饋、減少動態、彈道虛線、我的暱稱、伺服器連線檢查
  與恢復預設；支援遮罩點擊、Escape、焦點鎖定與關閉後焦點歸位。
- **🎮 對戰設定**只在真正進入戰場後顯示，另開獨立 Modal，提供重新開始、投降與離開對戰；
  等待房間與其他畫面不顯示這個入口。全域設定**重新載入後仍然保留**。
- 音效與背景音樂都是 Web Audio **即時合成**，沒有外部音檔、沒有授權問題；
  依瀏覽器規定會在第一次點畫面之後才解鎖。**全部靜音也能完整遊玩**，
  重要資訊一律有文字。

## 8. 專案結構

```
cat-dog-war/
```

### 架構重點

- **單一規則核心**：`public/js/rules.js` 是唯一的規則來源。
  本機玩家、三段 AI、線上伺服器都只能透過 `legalShot` / `applyShot` 改變狀態。
  伺服器用 `require('./public/js/rules.js')` 載入**同一份檔案**，不會有兩套規則漂移。
- **純函式 + 可注入亂數**：`applyShot` 不改動輸入狀態；
  地形來自 `seed`、每回合的風來自 `seed + 回合數`，所以重播、AI 測試與多人同步都可重現。
- **伺服器權威**：用戶端送的是「意圖」，伺服器驗證房間成員、角色、回合與合法性後才更新狀態。
  畫面上的按鈕開關只是方便，真正的把關在伺服器。
- **角色投影**：`viewFor(id)` 回傳每個人該看到的內容與 `you.can` 權限旗標；
  觀戰者拿不到邀請 token。

## 10. 環境變數與 server URL 參數化

完整清單見 [`.env.example`](.env.example)。

| 變數 | 用途 | 預設 |
| --- | --- | --- |
| `PORT` | 伺服器監聽埠 | `3020` |
| `HOST` | 監聽介面 | `0.0.0.0` |
| `GAME_ALLOWED_ORIGIN` | 允許的前端來源，逗號分隔；`*` 不限制 | `*` |
| `ROOM_TURN_MS` | 每次出手時限（毫秒） | `15000` |
| `AI_THINK_SCALE` | 電腦思考延遲倍率（設 0 可跳過思考與播放緩衝） | `1` |
| `GAME_SERVER_URL` | 前端要連的伺服器位址（**只有前後端分開部署時才需要**） | 空＝同源 |

### server URL 的解析順序

前端**唯一**的連線設定入口是 `public/js/config.js`：

1. 網址參數 `?server=https://...`（臨時覆蓋，跨電腦測試最方便）
2. 建置時注入（`scripts/inject-server-url.js` 改寫 `INJECTED` 那一行）
3. **同源**（頁面本身就是這台 server.js 送出來的 → 直接連回同一台）
4. 都不是（例如用 `file://` 打開）→ 只能玩單機，線上按鈕會停用並說明原因

規則：必須是 http/https 的絕對網址；https 頁面不接受 http 伺服器（混合內容會被瀏覽器擋）。
格式錯誤會被擋下並在設定彈窗顯示原因，**不會靜默回退到 localhost 或任何寫死的網域**。
`npm test` 有專門的測試確認版控裡的 `config.js` 沒有被寫死成任何網域。

```bash
# 分開部署時，在 CI 的建置步驟注入
GAME_SERVER_URL=https://cat-dog-war.onrender.com node scripts/inject-server-url.js

# 還原成同源
node scripts/inject-server-url.js --clear
```

## 11. 部署到免費雲端

### GitHub Pages（前端）＋ Render（伺服器）

這是目前這個 repo 設定好的組合：

| 放什麼 | 在哪裡 | 網址 |
| --- | --- | --- |
| 前端畫面、規則、AI、單機模式 | GitHub Pages | https://pjh-eric.github.io/cat-dog-war |
| 線上對戰的 Socket.IO 伺服器 | Render | 你的 Render 服務網址 |

**推上 `main` 就會自動部署**，由 `.github/workflows/deploy-pages.yml` 執行：
`npm ci` → `npm test` → 注入伺服器位址 → 上傳到 Pages。
測試沒過就不會部署，壞掉的版本不會被推上去。

#### 要設定的東西（一次就好）

1. **開啟 Pages**
   repo → Settings → Pages → Build and deployment → Source 選 **GitHub Actions**。
   （不要選 "Deploy from a branch"，這個 workflow 是用 Actions 部署的。）

2. **把 Render 網址設成 repository variable**
   repo → Settings → Secrets and variables → Actions → **Variables** 分頁 →
   New repository variable：

   | 欄位 | 值 |
   | --- | --- |
   | Name | `GAME_SERVER_URL` |
   | Value | `https://你的服務.onrender.com` |

   建置時 `scripts/inject-server-url.js` 會把它寫進 `public/js/config.js`。
   這是**變數不是 secret** —— 它本來就會出現在前端程式碼裡，沒有保密的意義。

3. **在 Render 那邊放行 Pages 的來源**
   Render 的 `GAME_ALLOWED_ORIGIN` 要填 GitHub Pages 的網址：
   `https://pjh-eric.github.io`
   （只填網域，不含路徑。填 `*` 也會動，但正式環境建議明確指定。）

改了 `GAME_SERVER_URL` 之後，要重新跑一次 workflow 才會生效：
repo → Actions → 「部署到 GitHub Pages」→ Run workflow。

#### 沒設定 `GAME_SERVER_URL` 會怎樣？

還是會正常部署，**單機對戰完全可以玩**；只有線上對戰會顯示「連不到遊戲伺服器」。
workflow 會在 Actions 記錄裡留一則警告提醒你。

#### 臨時指定伺服器

不想改設定、只想試一下的話，直接在網址後面加參數：

```
https://pjh-eric.github.io/cat-dog-war/?server=https://你的服務.onrender.com
```

網址參數的優先權高於建置時注入的值，方便臨時切換到別台伺服器測試。

### Render（推薦，免費方案支援 WebSocket）

1. 把這個 repo 推到 GitHub。
2. Render → **New > Blueprint** → 選這個 repo，它會讀取 `render.yaml`。
3. 環境變數 `GAME_ALLOWED_ORIGIN`：
   - 前端和伺服器都在這個服務上 → 填 `*` 或服務自己的網址。
   - 前端另外放（GitHub Pages 等）→ 填那個前端網址。
4. 部署完成後把服務網址（例如 `https://cat-dog-war.onrender.com`）給對方，
   兩台電腦直接開這個網址就能對戰。

| 設定 | 值 |
| --- | --- |
| Build command | `npm ci --omit=dev` |
| Start command | `node server.js` |
| Health check path | `/health` |
| Node 版本 | 20 |

### 免費方案的實際限制（請先知道）

- **會休眠**：閒置約 15 分鐘後服務睡著，下一次連線要等十幾秒冷啟動。
  前端在等待時會顯示狀態而不是無限轉圈。
- **檔案系統是暫時的**：不要在上面存任何需要保留的東西。
- **房間只存在記憶體**：服務重新部署或重啟，所有房間會消失（前端會提示並回到大廳）。
  這是刻意的設計——房間被當成可拋棄的暫時狀態，沒有任何長期資料需要保存。
- 有連線數、CPU、頻寬與每月建置次數配額，實際數字以平台當下的公告為準。

### 查看記錄與回滾

- Render 的 **Logs** 分頁可以看伺服器輸出（啟動資訊、錯誤）。
- 健康檢查：`GET /health` 會回 `{ ok, uptimeSec, rooms, sockets }`。
- **回滾**：Render 的 Deploys 分頁選上一個成功的 commit 按 *Redeploy*；
  或在本機 `git revert` 之後重新推上去。每一次部署都對應一個 Git commit。

### 尚未完成、需要你自己動手的事

以下步驟需要登入或帳號授權，**沒有代為執行**：

- repo → Settings → **Pages** → Source 選 `GitHub Actions`（第一次要手動開）。
- repo → Settings → Secrets and variables → Actions → Variables → 新增 `GAME_SERVER_URL`。
- 註冊 Render（或其他平台）帳號、連結 GitHub、按下部署，並設定 `GAME_ALLOWED_ORIGIN`。
- 設定自訂網域（如果需要）。

| 項目 | 現況 | 要換成正式版時 |

| 按鈕與 LOGO | 依元素尺寸即時繪製的 SVG，文字仍是 HTML（可本地化、螢幕閱讀器讀得到） | — |

沒有使用任何第三方圖檔或音檔，因此沒有授權問題。

### 已知限制

- **地形完全不會被破壞**，貓狗的位置也固定不動。這是刻意的：
  同一組角度力道整局都打到同一個點，玩家抓得到準心，回合之間也不用重新試距離。
  代價是沒有「把圍牆轟開」這種戰術。
- 道具是**開局各一個、用完不補**，沒有補給或掉落機制；
  原作的寶物是打中寶箱才拿得到，這裡簡化成固定配給，兩邊完全對稱。
- 一回合**只能用一個道具**，選定後不能更換；按「↺ 重置」只重設角度／力道，不會解除道具鎖定，也不能疊加（例如雙擊＋大骨頭）。
- 沒有帳號與永久排行榜；戰績只存在各自瀏覽器的 `localStorage`。
- **極窄或極矮的視窗**（例如高度小於 300px）會犧牲提示文字與裝飾，
  優先保住戰場、血量與道具 HUD；再小就不保證可用。
- 線上房間全部在單一伺服器的記憶體裡，沒有水平擴充或跨實例同步。
